# rclone-deck

> 文件放在 R2 里，在本地改完同步上去；云端哪天也变了，它会告诉你哪边新、哪边要留。

它只在你自己的电脑上跑，干的事就一件：把你本地的文件和 R2 / S3 上那份对到一起——本地改了，替你传上去；云端多出来的，可以删掉（删之前会先问你）。除了你自己已经配好的那个网盘，它不往别处发东西。密码不会显示在这块界面上，写日志之前也会先抹掉。（上面那张图是拿演示用的假文件跑的，所以名字里带着「（夹具）」两个字。）

## 支持范围

| 方面 | 范围 |
| --- | --- |
| 系统 | Windows 10 / 11（x64）。其他系统没测过，不写「应该能用」 |
| 要先装 | rclone（实测用的 v1.75.1）。面板自己把它跑起来当后台，你不用开命令行 |
| 网盘 | rclone 支持哪家就能用哪家（S3 / R2 / WebDAV / 本地文件夹……）。密钥你自己在 rclone 里配，它不管 |
| 界面语言 | 只有中文。所以这里也只放一份中文 README |
| 主题 | 浅色 / 深色 / 跟随系统 |

## 能做什么

- **本地和云端配成一张卡。** 选好哪边是本地、哪边是云端，再选这一次要干什么——每个选项自己就是一句完整的话（`只补，不删 —— 从本地补到云端` / `让两边对齐（会删） —— 以云端为主（删本地多余的）`），不用拼起来才读得懂。
- **先看，再动。** 「看差异」列出两边哪里不一样，只看不改。「看看会动什么」告诉你这一趟会动哪些。
- **要删东西的地方只有两处。** 一处是卡上「让两边对齐（会删）」那一档；另一处是「浏览文件」里的「删掉这一层看到的 N 个」和「清空这一层」，动的就是你点中的那些名字。**其余动作都不删东西**——「看差异」「对账」只读。
- **两边都有、但不是同一份，它单独列出来。** 这是最要紧的一类：同一个文件名在两边都在，别处的工具一般只比「谁在谁不在」，于是它两边都不算，按上传就把云端那份覆盖了。「差异」那一面第三张表就是它，并且**说得出哪边比较新**——你不用自己去比时间戳。
- **删之前一定会问你，而且说清删哪边。** 确认层会复述这一趟的方向和范围：本地是全集，还是云端是全集。你可以直接批，它替你过两道闸——要删的占比过半、或者有一边是空的，都不跑。想先看每个名字也行，点一次「重新预览」，它会重新列一遍逐条比对，对不上就不动。
- **跑完有账。** 每一趟落一份日志，密码先抹掉；跑完那一栏还挂着这次的清单快照，事后能查当时到底删了什么。
- **临时试一次不用存。** 想试一对没用过的目录，走「浏览文件」，跑完不留在配置里；觉得常用再「存成常用」。

## 快速开始

1. 装好 rclone，并用 `rclone config` 把远端配出来（这块界面不管凭据，也不显示它们）。
2. 打开 rclone-deck。**第一次打开时顶栏会红着写「后台没能启动」**——它还不知道你的 rclone 装在哪。去「设置」里的「rclone 程序在哪」那一格，填你在终端 `where rclone` 查到的第一条路径，然后**重开面板**。之后顶栏那盏灯变成「后台就绪」就成了。（面板不替你猜在哪：本机有两份 rclone 时，随便挑一个可能挑错。）
   端口你不用管，面板会自己挑一个当下没人占的。顶栏「详情」里显示的永远是**实际**在用的那个号。
3. 在「配好的位置」那一面挑一对位置，要做什么先站「只补，不删」。
4. 按「看差异」，看清要动的是哪些名字。第一次跑建议就停在这儿。
5. 觉得对了再按「开始」。要删东西得把「要做什么」换成「让两边对齐（会删）」，那一档会先开一个确认层把这一趟的范围与方向复述给你；要看逐条名字，按层里那颗「重新预览」。

装的是没做代码签名的包，Windows 会弹「未知发布者」，那是自签证书的正常表现。不想凭信任接受就自己编一份——闸门和构建步骤见 [CONTRIBUTING.md](CONTRIBUTING.md)。

跑完想查账：顶栏「详情」里能打开日志目录，每一趟一份。

## 限制

- **默认那一趟不列名字**：在确认层直接点确定就动手。想先看每个名字，多点一次「重新预览」。所以默认批的是「这一趟」而不是「这批名字」——面板替你守着两条：要删的占比过半、或者有一边是空的，都不跑。跑完删了哪些，查那一趟的日志。
- **浏览本地文件夹时直接看图。** 「浏览文件」左边那一栏是本机上的东西，所以图片直接摆出来，不用点任何按钮；点一下看大图。右边云端那一栏只给名字——那些文件本机没有，看它得先下载下来。
- **待上传的那批也能看图。** 「差异」那一面「本地有、云端没有」那一栏点一下「看看」出缩略图，点开看大图。一屏二十个 `IMG_2841.jpg` 谁也分不清，看一眼就知道是哪几张。
- **只有云端那一侧看不了图。** 要看就得先下载，而且不能只对一批做（那是另一件事，还没做）。
- **默认不按内容逐个核对。** 「两边都有、但不是同一份」这一列先比文件大小和修改时间——绝大多数情况这就够了。想更严（内容也逐个核对）在 `jobs.toml` 的 `[defaults]` 里加 `check_by_hash = true`，但那一次盘会明显变慢（几千张图的库要以分钟计）。
- **改完配置要重开才生效**：动过配置不会立刻生效，重开面板才行（界面上也会这么说）。
- **大目录慢**：六千个文件的目录，按文件名一个个比，实测五十多秒。换成「只比大小」能到十几秒，代价是「内容改了但大小没变」的文件不会再传一次——这一枚开关在界面上会一直说明白。
- **不记住你上次选了什么**：重开一定回到最轻的那一档「只补，不删」。记住一个会删东西的选择，等于让某天的第一次点击落在最重那一档上。
- **不是 rclone 的完整前端**：只管复制 / 对齐 / 上传 / 下载 / 改名 / 删这一类日常动作；加密远端、挂载盘这些不管。
- **新建网盘还得开终端**：面板能改已经配好的远端（类型 / 存储商 / 地址 / 区域四项），但新建一个远端还是得先跑 `rclone config`。密钥那一格它只读不写。
